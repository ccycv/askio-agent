## Changes since 0.4.41

From ccycv/askio-agent#8, after the 2026-11-24 fleet update left 8 gateways and the 8 hosts behind them on 0.4.39:

- **Gateway self-update.** The gateway poller accepts a typed `update_agent` command (`binary_url`, `binary_sha256`, `target_version`). It never runs a backend script. The binary is fetched over HTTPS only, checked against the SHA-256 and a size bound, and must report exactly the target version. It is staged in an exec-capable directory (never `/tmp`) and installed as root, through the root-owned `askio-monitor-updater` path unit, or through `sudo askio-ops self-update`. Missing privilege paths produce a clear "reinstall" error.
- **Sudo-mode systemd unit.** `PrivateDevices`, `RestrictSUIDSGID` and `LockPersonality` are emitted only for the migration profile, because systemd sets no_new_privs for a non-root `User=` whenever any of them is present, which broke sudo. The migration-profile unit is unchanged byte for byte.
- **`SystemdRunExecutor` fallback.** When sudo refuses to start `systemd-run`, the command runs directly instead. A start marker distinguishes the outer refusal from output inside the script, so a command that started is never re-run.
- **Daemon** skips a V2 command id it already started, and hosts reject the gateway-only `update_agent` type with a clear error.

## Rollout notes

- Gateways already in the field (0.4.39–0.4.41) cannot receive this release remotely. Each needs one in-place `agent-install.sh upgrade` (Askio ccycv/askio#101), which keeps the gateway's certificate, HMAC key and host tokens.
- Askio gates gateway updates on `GATEWAY_SELF_UPDATE_MIN_VERSION = "0.4.42"`.
- Rollback target: `0.4.41` (above). Keep `0.4.41` in Askio's `compatible_agent_versions` during a rollback.
