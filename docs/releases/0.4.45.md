## Changes since 0.4.44

Production 2026-11-27: on 25 `v2-instance-*` hosts the first inventory cycle on 0.4.44 never returned. Each claimed one request and then reported nothing for over 20 minutes, despite the 120 s capture deadline: a host read that ignores its context (most likely a file read on a hung mount during origin verification) held the capture.

- **Every passive host call of a capture is bounded.** The package-state and platform reads stop being waited for after 20 s and the package query after 45 s. A call that does not return is abandoned (it cannot be interrupted) and the capture continues as incomplete (`platform_timeout`, `query_timeout`, or an unstable capture).
- **A hung origin verification is abandoned.** Verification runs on a copy of the package list and stops being waited for after 60 s, or 20 s before the capture deadline. The packages are then uploaded with every origin `unknown` and the report error `verification_abandoned`. While an abandoned verification has still not returned, the next capture skips verification (`verification_still_running`) instead of starting another.
- **The heartbeat reports the step in progress.** `inventory_status.in_progress` carries the step (`claim`, `collect:package_state`, `collect:platform`, `collect:package_query`, `collect:provenance`, `collect:package_state_after`, `prepare`, `upload_page`, `complete`) and since when. A cycle that is stuck keeps reporting where. A request refused locally before collection is now recorded too (`last_cycle.stage = validate`).
- The monitoring heartbeat interval, config poll and every other loop are unchanged.

## Rollout notes
