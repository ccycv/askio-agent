## Changes since 0.4.40

- **Remote inventory switch.** This is a security-relevant change. The backend can now turn passive inventory on for an enrolled host. See [ENROLLMENT.md](../ENROLLMENT.md#host-gate) and [PASSIVE_INVENTORY.md](../PASSIVE_INVENTORY.md#enablement).
  - `inventory.enabled` in the local config is now tri-state:
    - absent: follow the backend;
    - `false`: hard local deny, which the backend cannot override;
    - `true`: local opt-in, as in 0.4.40.

    The installer still never writes the key.
  - `monitor-agent-config` may carry `"inventory": {"enabled": true|false}`. With the local key absent, remote `true` is honoured only in direct host mode, with no gateway stanza, a fixed HTTPS API URL and verified TLS. Otherwise the agent stays off and logs the refusal reason once.
  - The inventory loop starts and stops within one config poll of the gate changing. Stopping cancels the loop, so no further claim, page or completion is sent.
  - A remote switch cached on disk is not honoured until a live poll confirms it.
  - Backend enrollment and every claim-side check are unchanged.
- **`askio-monitor status`** gains an `inventory` field: `local-on`, `local-off`, `remote-on`, `remote-off` or `remote-refused:<reason>`.
- **Gate tests.**
  - The matrix grows from 24 to 72 cases: 3 local × 3 remote × 8 backend states.
  - New tests cover:
    - unsafe-composition refusal;
    - the local hard deny;
    - ON→OFF→ON toggling through the real config poll loop;
    - a local `true` ignoring remote OFF;
    - a cached switch needing a live poll.
- **What did not change:**
  - no file under `internal/migration`, `internal/operations`, `internal/remediation`, `internal/discovery`, `internal/checks`, `internal/gateway`, `internal/audit`, `internal/store`, `internal/api` or `internal/vulnerability`;
  - neither `go.mod` nor `go.sum`;
  - nothing on the inventory wire protocol or in the claim body.

## Behaviour with the backend's inventory flag off

The backend omits the `inventory` field while `VULNERABILITY_INVENTORY_ENABLED` is off. A host whose local key is absent is then `remote-off` and sends no inventory request. Hosts with a local `false` or `true` behave as in 0.4.40. The lab parity run, in the form of the [0.4.40 table](0.4.40.md#behaviour-with-the-backends-inventory-flag-off), is to be filled at release build. It should add two rows: local absent with remote `true`, and local `false` with remote `true`.

## Rollback

Restore the previous Askio release metadata and binary, which is `0.4.39`, the last promoted release.

- **Hosts keep 0.4.41 until each is updated.** The per-agent update installs the pinned binary; the update script does not refuse a downgrade.
- **The remote switch becomes inert.** 0.4.40 and 0.4.39 ignore the `inventory` field of `monitor-agent-config`, because the remote config decoder ignores unknown fields.
- **Local settings keep their meaning.** 0.4.40 reads `enabled: true` and `enabled: false` the same way. 0.4.39 ignores the stanza.
- **Keep `0.4.41` in Askio's `compatible_agent_versions` during a rollback.** The deploy guard blocks a backend deploy while any active migration run is bound to an agent version missing from that list.
