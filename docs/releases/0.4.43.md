## Changes since 0.4.42

From ccycv/askio-agent#10:

- **Package origin from signed indexes (`signed-index-v1`).** For every installed package whose source is in the evaluated vulnerability scope (nginx, apache2, php8.3/8.4, openssh, openssl, glibc, systemd, sudo, curl), the agent looks for the exact binary name, architecture, version, source and source version in a signed official Ubuntu 24.04 / Debian 13 `Packages` index. The `InRelease` signature is checked against the pinned archive keys, and the index digest against `InRelease`. Every file listed in the package's root-owned dpkg `md5sums` must match on disk.
- It replaces `cached-deb-chain-v1`, which needed cached `.deb` files that production hosts do not keep. The capability (`vulnerability.package-provenance.v1`), collector (`dpkg-passive-v2`) and trust policy are unchanged.
- **Known limits (accepted by the owner):** a same-version local rebuild is not detected, and a build that is no longer listed in the index (a pending update) stays `unknown`.
- Bounds: at most 128 receipts, 8,192 installed files and 1 GiB of installed bytes per report.

## Rollout notes

- Requires the Askio backend from ccycv/askio#103 (deployed 2026-11-25 as `d1ad6674`), which accepts both verifiers. Do not promote it to an environment running an older backend.
- Nothing changes on a host until Askio sets `VULNERABILITY_PROVENANCE_ENABLED=true` (trial runbook step 6). Updating the agent does not enable it.
- Rollback target: `0.4.42` (above).
