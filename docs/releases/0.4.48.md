## Changes since 0.4.47

0.4.46 and 0.4.47 refuse every release other than Ubuntu 24.04 and Debian 13 (`unsupported_platform`, `unsupported_provenance_platform`). Production has 14 agents on Ubuntu 22.04 and 2 on Debian 12 (2026-11-28); Askio's backend evaluates both since ccycv/askio#134 and Ubuntu 26.04 since the companion Askio PR.

- **Inventory on five releases.** The collector accepts Ubuntu 24.04, 22.04 and 26.04 and Debian 13 and 12 on amd64. One profile per release (`internal/vulnerability/release_profiles.go`) holds its codename, distribution PHP branch (php8.3, php8.1, php8.5; php8.4, php8.2), keyring path, verifier and signer pins. Ubuntu 24.04 and Debian 13 are exactly the 0.4.47 rules.
- **Origin verification on the new releases.**
  - Ubuntu 22.04 and 26.04: gpgv with the same non-expiring Ubuntu archive 2018 key as 24.04, which signs every jammy and resolute pocket.
  - Debian 12: sqv with the bookworm archive, stable-release and security keys (`B8B80B5B…`, `4D64FEC1…`, `05AB9034…`), the security key only for `bookworm-security`. Bookworm's keyring is `debian-archive-keyring.gpg` (no `.pgp`), and its sqv 1.1.0 takes the signature as a positional argument. **Bookworm's apt does not install sqv**: hosts need `apt install sqv` (Debian main) or every origin stays unknown, which is the safe failure.
- **Trust policy v3.** Reports name `ubuntu24.04-ubuntu22.04-ubuntu26.04-debian13-debian12-archive-v3`. The backend's v2 name lists only four releases, so v3 is v2's per-release rules plus Ubuntu 26.04. Askio's provenance contract admits v3 for all five releases.
- **Larger InRelease files.** The InRelease read and cleartext bound is 1 MiB (was 256 KiB): jammy's base InRelease is 270,087 bytes, so 0.4.47 could never verify a package from the jammy pocket; noble's is 255,850.
